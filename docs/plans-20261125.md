# Plans and checkout (25 November 2026)

**Status:** built on the branch `feat/plans-checkout`. Off everywhere except the development server and the test harness. Nothing deployed. **No real payment code:** no payment company is connected and no money can move.

## What it is

- **Three plans:** Free, Plus and Pro, in `shared/plans.ts`.
- **A "Plans" entry in the account menu** (only while the switch is on): the three plans side by side (one under the other on a phone), yours marked "Your plan", a button to choose another.
- **A checkout that does not know any payment company.** The server has one small interface (`CheckoutProvider` in `server/plans.ts`): start a checkout, and later say what became of it. Stripe, Paddle or another company would each be one file that fills this interface.
- **A fake provider for tests:** a plain page that says "No money moves" with "Pay (test)" and "Cancel". It is what the development server and the tests use.

## How a plan changes

1. "Choose Plus" asks the server to start a checkout. The server asks the provider and answers with the address of the provider's page.
2. The browser leaves CometRow for that page.
3. The provider sends the browser back with the checkout's id.
4. The app asks the server "what became of it?". **Only the provider's answer counts**, never what the page claims. Paid: the account is on the new plan. Cancelled or still open: nothing changes.
5. One checkout sets a plan once, and only for the account that started it.

"Switch to Free" needs two presses and no checkout.

## Decisions taken (all yours to change)

1. **Every number is a proposal.** Your decision list says plan values are reviewed before launch, so nothing here is final.
   - Free and Plus show the limits already proposed in `shared/usage-plans.json` (its "free" and "premium").
   - Pro had no numbers anywhere. I set it to about four times Plus.
   - Prices: EUR 20 and EUR 200 a month, the same figures as ChatGPT Plus and Pro (your rule for an open decision). **I would not launch with EUR 200:** ChatGPT's Pro buys things CometRow does not have. A Pro at EUR 40 to 60 fits better; say the number.
2. **The limits are shown, not applied.** Today one usage plan applies to the whole deployment (`inference.metering.plan`). Making limits depend on each account's plan touches the metering in many places and was not done.
3. **No database table yet.** The plan is kept in memory, which is enough for the development server and the tests. The table (migration 0030 is reserved) belongs to the first real provider: without one, production has nothing to store.
4. **No switch in the deployment config.** With the limits not applied and no payment company, the screen would promise things production does not keep. So it cannot be turned on there at all (a test checks this). It comes with the two steps under "What is missing".
5. **The older "Subscription rehearsal" screen is untouched.** It is tied to Stripe's test mode and production refuses it. The new interface can replace it once you choose a payment company.

## What is missing before real use
