# Working rules (owner, 25 November 2026)

Standing rules for this work and for every later session. They add to `docs/owner-decisions.md`; they do not replace it.

## 1. UI references

- When a screen would be better for seeing how ChatGPT, Claude or Gemini do it, the agent does not guess everything from scratch and does not wait for the owner.
- The agent adds a numbered request to the section **"UI references I need"** in the "Needs you" part of its report. Each request says: which screen, which state (empty, filled, error, phone), and what is to be compared.
- Meanwhile the agent builds its best version.
- After the exams the owner sends screenshots, and the agent improves the screens from them.
- The goal is to be as good as them or better, not to copy.

## 2. Request log

- The agent keeps `docs/owner-requests-log.md`.
- Every request from the owner gets an entry, including those already sent since the first message of 25 November 2026.
- An entry holds: the date, the request in short, what was done and how, the branch and commit, the test results, and the status (done, partly or open, and why).
- A new request is added when it comes, not at the end.
- The owner keeps track through this file, so it stays complete and current.

## 3. Earlier standing rules from the same day (for one place to read them)

- **A brief is a suggestion.** A better idea or approach may be used if it is written down. The protective rules stay: no deploying, no spending beyond what was allowed, nothing merged into the owner's branch, no deleting.
- **Light and dark.** Everything built is looked at in both.
- **How answers look is where CometRow can win.** Normal chat, search and deep research answers get real time and effort: organised, beautiful, interactive and graphical where it helps.
