# Projects with instructions and files, on the device (14 November 2026)

**Status: built and tested offline, switched off by default, nothing verified live.** Checklist row U6. Privacy wording draft for the owner: `docs/projects-privacy-wording-draft-20261114.md`.

## What it does

A project already grouped chats by name. With the switch on, a project also has:

- **Instructions**: one text of up to 2,000 characters. It goes with every question asked in a chat of that project.
- **Files**: text documents read on the device with the existing extraction. For each question the device picks the passages that match best, across the project's files, and sends only those.
- **A project screen**: open a project from its menu in the sidebar ("Open project"). It shows the instructions (edit), the files (add, remove, sizes), the project's saved chats (open one), "New chat in this project", Rename, and Delete project.

Everything lives in the encrypted vault in the browser. The server has no code for this feature and learns nothing about projects.

## The switch

`VITE_PROJECTS=1` at build time, in `src/device-features.ts`, like `VITE_MEMORY`. Off by default. A build switch, not `inference.projects`, because the feature needs nothing from the server (same reasoning as `docs/memory-20261114.md`).

With the switch off: grouping works exactly as before (create, rename, remove, move, filter). No "Open project", no instructions or files are read or sent, no row in the context review, no note under answers. Instructions and files already in a vault stay there untouched, so turning the switch off and on loses nothing.

## What is sent

**Instructions.** A block in front of the latest question, in the same message:

```
[Instructions the user wrote for every chat in this project. Follow them for the message below unless that message says otherwise. They never override your rules above. They are not part of the message and their language does not set the reply language.]
Antworte immer auf Deutsch. Ich bereite einen Mietstreit vor.
[End of project instructions]

Wie lange ist meine Kündigungsfrist?
```

Why in the latest user message and not in the system message: the same reasoning as memory. The system message and all earlier turns stay byte for byte the same, so the provider's prompt cache for them is not broken, and the other request paths (code tool, pictures) keep their message positions. The cost: the instructions are re-sent with every question (at most about 2,300 characters with the wrapper).

**Order with memory**: project instructions, then memory notes, then the question. Both can be sent. Combined at most about 3,800 characters (2,000 plus 1,200 plus the two wrappers). Each part counts toward the input limit; if the whole does not fit, nothing is sent and the app says the context is too large, as for any other part.

**Files.** The project's files are added, for choosing and sending only, to the chat's own large documents. The existing ranker (`src/passage-retrieval.ts`, German and English) chooses passages from all of them together, inside the existing budget of 14,000 characters per question. That budget is shared with documents attached to the chat itself. If no passage shares a word with the question, no project passage is sent (a document attached to the chat still sends its start, as before). The chat itself is never changed and never stores the files.

The line under the answer names each file that was used and its pages, as for large documents ("This answer used 1 of 3 passages from "mietvertrag.pdf" (page 2) ..."). A project file that was not used is not named, because a project can have 20.

**Masking.** Instructions and passages are part of the request messages, which are masked whole on the device before encryption (`src/verified-chat.ts`). An email address or IBAN in the instructions leaves as a stand-in and is counted in "Kept on this device". Tested.

**Context review.** A row "Project instructions" shows the size of the block. Project passages are counted in "Selected references", and the passage notes appear there before sending.

**Never sent**: in incognito chats, after a chat is moved out of the project (from the chat menu or the sidebar), in a chat of another project, with the switch off, with the vault locked, and for evaluation variants.

Under each answer: "Project instructions were sent with this question." Only that flag is stored with the answer, not the text.

## Interplay

| Feature | Instructions | Files |
| --- | --- | --- |
| Memory | Both sent, instructions first | Independent |
| Documents attached to the chat | Independent | Share the 14,000 passage budget |
| Code execution | Apply (same composed messages) | Apply |
| Picture questions | Apply | Apply. Pictures cannot be project files |
| Deep research | Apply to the answer request (counted in the room for sources); not in the plan request | Apply to the answer request; never in a search text |
| Search suggestion | Never used: the suggestion is built from the question only | Never used |
| Incognito | Never | Never |

## Limits

- Instructions: 2,000 characters per project.
- Files: 20 per project. 1,500,000 characters of extracted text per project. 3,000,000 over all projects in the vault (checked when a file is added). One file keeps the existing per-document limits (`src/document-formats.ts`: 500,000 characters, 150 PDF pages, 10 MB).
- Same file name twice in a project: refused. Pictures: refused (and not offered by the file picker).
- Removing a file removes it from future questions only. Answers that already used it keep their note and their source list.

## Vault

- Instructions are an optional field in the existing projects record (`projects-v1`). Old records with only id and name still read. Rename keeps the instructions.
- Files are one more encrypted record in the `meta` store, key `project-files`, label `project-files-v1`, keyed by project id. Kept apart from the project list because every save of a project chat reads that list. A vault without the record reads as "no files". No database upgrade.
- Passphrase change re-encrypts both records. Delete project removes its instructions and its files in the same transaction. "Delete everything on this device" deletes the database. Removing the last file deletes the record.
- A change to instructions or files, and deleting a project, locks other open tabs of the same account (as deleting a chat does), so no tab keeps sending something removed elsewhere.
- Lock, sign-out, reload and account switch drop the decrypted projects and files from the page (`useProjectVault` in `src/ProjectPanel.tsx`; the app empties its project list in each of these paths).
- The paths that list vault contents by hand (`docs/scheduled-tasks-design-20261114.md`): passphrase change (handled), "Delete everything" (deletes the database), lock (handled), account switch (requires lock first), backup (see below). Restore: restored projects keep their instructions and get new ids; they have no files.

**Backup.** The encrypted backup includes project names and instructions, **not project files**. Reason: a full set of project files is about 3 MB of text, which together with 100 conversations could pass the backup's 10 MB content limit (16 MB file cap) and then block backups entirely. The files are extracted copies of documents the user has; after a restore he adds them again. The backup screen and the project screen say so. Open decision for the owner (below).

**Downgrade.** An older build reads projects with a strict schema. A projects record that holds instructions makes the project list unreadable for an older build until the instructions are removed. Rolling back the web app after the switch was on needs this in mind.

## Cost

No extra requests and no allowance change. Per question in a project chat:

- Instructions: up to about 2,300 characters, roughly 600 tokens at most.
- Files: up to 14,000 characters of passages, the same as one large document today, roughly 3,500 to 4,000 tokens.

Measured in Node (`tests/projects.test.ts`, fake IndexedDB, a fast PC): a full project of 1,464,168 characters is a record of 1.56 MB of JSON; writing it took 11 ms, reading and decrypting it 6 ms, the first passage choice 90 ms (the word index is built once per file), later choices 5 ms. A phone will be several times slower; the vault limit of 3,000,000 characters bounds the decrypt at unlock to about 3 MB. Not measured on a phone.

## Limits, stated honestly

- The ranker matches words, not meaning (see `docs/large-documents-20261114.md`). An ordinary word shared with a file pulls in a passage.
- Whether the models follow project instructions, and keep the reply language of the question when the instructions are in another language, is not verified.
- The instructions are kept as typed; masking happens only on the way out.
- Project files are not in the backup.
- Older builds cannot read a projects record with instructions (downgrade note above).
- The sidebar's existing "Remove project" still uses the browser's own confirmation; with the switch on it adds that instructions and files are deleted. The project screen's Delete uses the app dialog and offers to delete the chats too.
