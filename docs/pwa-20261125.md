# CometRow on the phone's home screen (25 November 2026)

**Status:** built on the branch `feat/pwa`. Nothing deployed. Not tried on a real phone: only you have the devices.

## What was already there

The web manifest (`public/manifest.webmanifest`) with the name, "open in its own window", the page colour and three icons (192, 512, and one that survives being cut to a circle), and the 180-pixel icon for iPhones. So "Add to Home screen" already gave the CometRow icon (your test 1.6).

## What is new

| | Android (Chrome) | iPhone (Safari) |
| --- | --- | --- |
| Install | Chrome's menu > "Add to Home screen" / "Install app"; or **Settings > General > Install CometRow** (behind its switch) | Share button > "Add to Home Screen"; the Settings row says so in one line |
| Icon | From the manifest, with the cut-safe version | The 180-pixel icon |
| Opens full screen, in its own window | Yes (manifest: standalone) | Yes (the page now carries the iPhone tags for it) |
| Name under the icon | CometRow | CometRow |
| Start screen | Android builds it: the icon and the name on the page colour | The app's own start screen (below) |

**The start screen:** the page now contains the CometRow mark, centred on the page colour (light or dark with the phone's theme), from the first moment. The app replaces it when it has loaded. It shows in every browser, so the first seconds are no longer a blank white page anywhere; on an iPhone it is what you see after the launch.

**Install CometRow in Settings** (switch `VITE_INSTALL_APP=1`, off by default): the row appears only when it can do something. On Android and desktop Chrome it starts the browser's own install. On an iPhone it explains the two taps. Once CometRow runs from the home screen the row is gone. With the switch off, the browser's own offer is left exactly as it is.

## Decisions taken

1. **No offline mode and no background worker (service worker).** Chrome has not needed one to install since 2023. A worker would keep a copy of the app on the device and decide when it updates; a stale copy after a deploy is a known source of "it still shows the old version" bugs, and CometRow needs the network for every answer anyway. One can be added later for notifications of scheduled tasks (you have put Web Push on the later list).
2. **One start screen in the page instead of iPhone launch pictures.** Apple wants one picture per screen size (about twenty). The mark on the page colour needs none of them and looks the same on every device.
3. **The switch covers only the Settings row.** The manifest, the iPhone tags and the start screen have no off-switch: they change nothing for someone who does not install.
4. **No "install me" banner.** The app never asks by itself (your rule: no pop-ups in normal use). The row is in Settings for whoever looks for it.

## Switch

Render environment variable `VITE_INSTALL_APP` = `1`, then redeploy (a build switch, like the others in `Dockerfile.render`).

## For your owner test (only a real phone shows these)

- Android: install, look at the icon on a round and a square launcher, open it: full screen, start screen, then the app.
- iPhone: Share > Add to Home Screen, open it: no Safari bars, the start screen, then the app.
- **Sign-in from the installed app.** Google sign-in leaves the app's window for Google's page and must come back into it. On iPhones this has differed between iOS versions. If it lands in Safari instead, sign in once in Safari before installing, or tell the agent.
- The notch and the home bar: nothing of the app under them.
- After a deploy: close and reopen the installed app; it shows the new version.
