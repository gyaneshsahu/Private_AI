# Deployment review checklist for public hosting — 22 October 2026

Launch plan 7.5. One row per PRD item, each with the control as built, how it is verified, and what remains the owner's. "Verified" means a test or CI step checks it on every push; "owner" means a step only the owner can perform or decide. `tests/deployment-review-checklist.test.ts` checks the machine-checkable rows against the repository, so this document cannot silently drift from the code. Nothing here authorises a deployment; the gates in READINESS.md stay closed until the owner closes them.

## Review procedure before any public deployment

1. Exact-commit CI green, including the in-image attestation CLI smoke on the clean runner.
2. The three candidate images rebuilt from that commit; the default build must succeed, which proves the policy placeholders are gone.
3. `check` reports the expected pending count, `apply-pending`, then `check` reports zero.
4. Deploy the exact commit; keep auto-deploy off.
5. One pass over the live origin: fixed headers present on a refused and on an accepted response, sign-in works for an allowlisted address, a second identity is denied, a sign-in code flood stops at the fifth code.
6. Record the release identity, the readings of steps 3 and 5 and the rollback target in READINESS.md.

Open items that this checklist does not close: the pinning policy for the attestation audit, hosted recovery rehearsal (7.1), abuse monitoring (7.3), and the hosted second-identity denial, all listed in the launch plan.
