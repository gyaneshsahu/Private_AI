# Image placement and sharing (25 November 2026)

**Status:** built on the branch `feat/image-share`, which starts from `feat/image-editing` (it builds on the image card and the editor). Step 2 (links) is behind a switch that is off. Nothing deployed.

## What a user gets

**Images in the chat**
- An image sits in the chat with **Edit, Download and Share**. A click on it opens the full-screen viewer and editor (full screen with Back on phones).
- On a computer: **Open in side panel**, the same panel the canvas and the whiteboard use. One thing at a time; **In this chat** leads to the list of everything in the chat, and the list opens the image again. On a phone or a narrow window there is no side panel, so the button is not shown.

**Share, step 1 (always there, nothing stored on a server)**
- A **Share** button on every answer, in the chat's own "⋯" menu (the whole chat), on every image, in the image editor and in the side panel.
- It opens one small dialog: **Share with…** (the device's own share menu, where the browser has one), **Copy text**, **Download** (a text file, or the picture).
- All three happen on the device. A browser test checks that none of them sends a request.

**Share, step 2 (encrypted links, switch off by default)**
- In the same dialog: **Share as a link**, with the sentence "Anyone with the link can see this.", an end date (1, 7 or 30 days) and **Create link**.
- Then: the link, **Copy link**, the date it ends, and **Delete link**. Settings > Data controls has **Shared links**: every link you made, by its dates, each with Delete.
- Whoever opens the link sees a plain page: the title, the question and answer (or the chat, or the picture), and "Someone shared this with you. Anyone with the link can see it." No sign-in.
- **No links from Incognito or Secure Max.** The dialog says so there. The device's share menu, Copy and Download still work in both, because they stay on the device.

## How a link works

1. The browser builds a **snapshot**: the title and the words of the turns (or the one picture). Not the attachments, sources, settings, account or other versions.
2. It encrypts the snapshot **in the browser** (AES-256-GCM, a fresh key for every link).
3. It sends only the encrypted bytes to our server, which stores them with your account, the time and the end date.
4. The link is `https://app.cometrow.com/s/<id>#<key>`. The part after `#` is the key. Browsers never send that part to a server, so we hold bytes we cannot read. A browser test checks that the key is in no request.
5. Opening the link: the page fetches the encrypted bytes for `<id>` and opens them in the reader's browser with the key from the link.
6. At the end date the link stops opening at once and the row is deleted at the next cleanup. **Delete link** removes it at once. Deleting the account removes all its links.

**What our server knows about a link:** which account made it, when, when it ends, and how large it is. Not what it shows.

**What this does not protect against:** anyone who gets the link can read it and can keep a copy; that is what a link is. Deleting a link does not take back what someone already saw or saved. A link in a chat app or an e-mail is as private as that app or e-mail.

## Decisions taken

1. **One dialog for every kind of sharing**, instead of separate buttons for share, copy and download on each thing. ChatGPT has a share dialog too; this keeps one more icon per answer, not three.
2. **A shared chat is its words.** Pictures in the chat are shared from the picture itself (one link, one picture), because a link holds about 3 MB and a chat can hold more pictures than that.
3. **Shared text is shown as plain text**, not as formatted answer text. Nothing in a snapshot can run or load anything from elsewhere, which matters on a page anyone can be sent to.
4. **Limits:** 50 links per account at a time; a link is at most about 3 MB. Over either, the dialog says so in one sentence.
5. **The reader's page is the app's own page at another address** (`/s/…`), which shows only the viewer and never asks for the account. No second page had to be built or allowed through the hosting bridge.
6. **Incognito and Secure Max are checked in the browser.** The server cannot know which mode a snapshot came from (it cannot read it), so a changed browser could still make a link from there. It is a rule for the app's own screens.
7. **No view counts, no list of who opened a link.** The public address records nothing.

## For the owner before switching links on

- **This replaces an older decision.** Item 17 of 16 November lists "shared links" as not built because of your rules. You asked for them on 25 November, behind a switch. Confirm before switching on.
- **Database:** `apply-pending` must run once for migration 0027 (the check then says `"applied":21`; with other new branches the number is higher), and the privileges SQL must be re-run so the app's database role may use the new table.
- **Privacy Policy, draft for the lawyer.** English: "If you make a share link, your browser encrypts what you share before it reaches us. We store the encrypted copy with your account until the link ends (after 1, 7 or 30 days, as you choose) or until you delete it. We cannot read it: the key is part of the link and is never sent to us. Anyone who has the link can read what you shared." German: „Wenn Sie einen Link zum Teilen erstellen, verschlüsselt Ihr Browser das Geteilte, bevor es uns erreicht. Wir speichern die verschlüsselte Kopie zu Ihrem Konto, bis der Link endet (nach 1, 7 oder 30 Tagen, wie Sie wählen) oder Sie ihn löschen. Wir können sie nicht lesen: Der Schlüssel ist Teil des Links und wird nie an uns gesendet. Jeder, der den Link hat, kann das Geteilte lesen.“
- **For the lawyer to weigh:** a link's content is the user's own publication to people he chooses; we host unreadable bytes. What follows for notices about unlawful content (we cannot inspect it, but can delete a link by its address) and for the Terms.
- **Abuse:** a signed-in account could use links as free storage for 50 files of 3 MB for 30 days. Accepted for an invite-only alpha; a daily creation limit is one line if wanted.
