## Privacy policy page

The policy page repeats the statement, so it follows the same variant. One more section has provider wording, "What we cannot delete for you":

- **Old:** "The secure server's short-term working memory, which clears on its own within minutes to a few hours and has no delete button. The provider's records of time, model and token counts, which the provider states it keeps for 90 days. Our own request records: which account asked, when, how many times, which model, and the published cost; we keep them for 90 days and then delete them. Search-provider records of search text you approved, kept under that provider's policy."
- **New (draft, `PRIVATEMODE_CANNOT` in `shared/privacy-policy.ts`):** "The secure server's short-term working memory, which is kept apart for each account and has no delete button. The provider's records of time and token counts, which the provider states it keeps for up to 90 days, and its token counts per key, which it keeps permanently for billing; we use one key for all accounts. Our own request records: which account asked, when, how many times and which model; we keep them for 90 days and then delete them. Search-provider records of search text you approved, kept under that provider's policy."

The provider section "Who processes your messages" (`shared/provider-disclosure.ts`, D8) already has a Privatemode entry and is unchanged.

## Open points for the owner

1. **Training sentence.** "does not use them to train any AI" is kept for Privatemode. Its source is the DPA's purpose limitation (§2), not an explicit training sentence (`docs/provider-promises-20261112.md` marks it "yes (purpose limitation; no explicit training sentence read)"). Approve as is, or replace with "uses them only to provide the service".
2. **IP address.** Privatemode's metadata includes the IP address of the caller. That is our server, never the user's (the relay), so the new text does not mention it.
3. **Conflict with the unmerged branch `privacy-wording-20261112`.** That branch rewrites the approved "sealed", "ours", "notyet" and summary texts in `shared/privacy-copy.ts`. This branch leaves those approved texts untouched but adds the Privatemode block and changes `privacyText()` below them, so a merge conflicts textually around `privacyText()` and needs a manual check: the new Privatemode "sealed" and "ours" texts restate the old Tinfoil sentences they share (for example "We never see what you asked"), so whatever the owner approves on that branch must be carried into the Privatemode variant by hand.
