# Threat model against CometRow's promise — 22 October 2026

Status: ledger entry prepared by the agent on 22 October 2026 from branch commit `7ce181a`, `docs/ARCHITECTURE.md` (sections 3 and 4, "What each party can see" and "Security decisions and failure behavior"), `docs/READINESS.md` (22 October entries), `docs/relay-mitigation-assessment-20261021.md`, `docs/provider-qualification.md`, `docs/backup-retention-policy.md` and `shared/privacy-copy.ts`. No code was changed and no supplier was contacted.

The promise being defended is the one-sentence summary in `shared/privacy-copy.ts`: "ID, bank and contact details stay on your device; everything else is sealed so only one checked secure server can read it, and we never can." The threat list is the one the brief asked for plus nothing invented; each row names what the design does today on this branch, what it does not do, where the evidence is, and a status. Status words: **mitigated** (the threat is addressed by tested code on this branch for the stated scope), **partial** (addressed in part, with a named gap), **open** (no effective control today), **out of scope** (not something the product promises to defend against; the privacy statement says so). "Locally tested" means the tests recorded in READINESS ran on the founder's machine; exact-commit CI and hosted verification are separate. **No row is a qualification claim; provider qualification remains NOT_PASSED and launch plan Phase 8 remains BLOCKED.**

## Cross-cutting notes

- **The weakest link for the promise is row 2 and row 3 together:** the browser can prove it is talking to an attested router running an approved release, but not that the release is still endorsed, not that the worker and GPU behind it are the ones audited, and not that the cache is empty. That is why private chat stays disabled and why the 23 October provider decision matters.
- **Metadata is not covered by the promise and never was.** Rows 1, 5 and 6 leak account, timing, size, model, token counts and approved search text by design; the privacy statement says "we know which account asked, never what".
- **Everything "locally tested" above still needs exact-commit CI and the hosted checks in launch plan 0.3** before it counts as evidence for an invitee.
- **This table is not a security review.** Independent review, load testing and a real-device pass remain open items in `docs/acceptance.md` and the launch plan.
