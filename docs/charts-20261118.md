# Charts in answers (18 November 2026)

Owner's brief, 18 November: build charts; one short rule for the AI (a chart only when the answer has 3 or more numbers over time or across categories); the app draws it (line, bar), in the new design, with a source line; report the extra prompt tokens and cost (approved up to about 300 tokens); test the rule on 20 questions in English and German with minimal spend. Image cards from web search: design and cost note only.

## What was built

- **The rule**, added once to the product prompt (`src/conversation.ts`, `productHead`):
  "Add a chart only when the answer has 3 or more numbers over time or across categories; otherwise none. Write it after the text as a ```chart block with JSON {"type":"line" or "bar","title","unit","labels":[...],"values":[...],"source"}."
- **The drawing** (`src/AnswerChart.tsx`): a finished ```chart block with 2 to 24 non-negative numbers becomes a line chart (over time) or a bar chart (across categories) in the answer, with title, unit, the highest point in the accent colour, and "Source: ..." under it when the model gives one. The same numbers are in a hidden table for screen readers. Anything else (not JSON, negative numbers, unknown type, too many points) stays an ordinary code block. Nothing is fetched; no library.
- **Not built**: pie charts, several series in one chart, negative values. Each would make the rule or the JSON longer; they can follow if real use asks for them.

## Does the model follow the rule? (live, GLM-5.3-Flash, 18 November)

`evaluation/charts/chart-rule-probe.mts`, results in `evaluation/charts/results-20261118.json` and `-rerun.json`. 20 synthetic questions, 10 English and 10 German; 10 should get a chart (yearly figures, comparisons of cities or foods, the user's own bills), 10 should not (a note, a capital, one percentage, an explanation, tips).

| | English | German | Both |
| --- | --- | --- | --- |
| No chart where none belongs | 5 of 5 | 5 of 5 | **10 of 10** |
| Chart drawn where it belongs | 4 of 5 | 4 of 5 | **8 of 10** |

The two without a chart:
- "How did Germany's population change from 2015 to 2023?": the model spent all its tokens reasoning about exact figures and gave no answer (at 900 and again at 2,500 tokens). A model limit for exact statistics, not the rule.
- "Hours of sunshine in four German cities": it answered with ranges ("1,700 to 1,800 hours") and left the chart out, which is reasonable.

Every drawn chart parsed cleanly; line for time, bar for categories, as asked. Not tested: Thinking mode, long conversations, answers with web sources (the `source` field then should name them; seen in the user-bills case as "your figures").

**Spend:** EUR 0.0099 (first run: 22 requests) plus EUR 0.0035 (rerun of 3) = **EUR 0.013**, one verification each.

## Second phase: image cards from web search (design and cost note, not built)

Goal: when a web search finds pictures that help (a product, a place, a plant), show a few small image cards with the page's name and a link, in the new design.

Design:
1. The search runs as today on the server. An image search (Brave Search image endpoint, safe search "strict") runs only when the user asked for a search and the question is about something visual; at most 4 results.
2. The server fetches each thumbnail itself (the user's browser never contacts the image host, so the host does not see the user's address), checks type and size (JPEG, PNG or WebP, at most 150 KB, decoded size at most 512 px), strips metadata, and passes it to the browser as data. Nothing is cached on the server beyond the request.
3. The browser shows the cards under the answer: picture, page title, site name, link "Open page". Pictures are saved with the conversation in the vault like other content.
4. The content rule stays as it is (`img-src 'self' blob: data:`): no picture is loaded from another site.

Cost (to confirm against Brave's price list when the owner decides): one extra image search per visual question (Brave Search API is priced per 1,000 queries; the image endpoint is billed like a web query), plus server bandwidth of about 4 x 50 KB per such question. No AI tokens.

Open points for the owner: the privacy page must name Brave as the search partner for images too; whether image cards count against the daily search allowance (proposal: yes, one search); the legal read on showing third-party thumbnails (proposal: thumbnails with a link to the source, as search engines do).
